# TourDesk — публикация на Render

## Текущее состояние (04.11.2026)

В базе Supabase «туры» (`guxkarncctfeiswevini`) уже установлены 12 таблиц, RLS и серверные RPC. Не выполняйте `001`/`002` повторно поверх работающей базы. В новом Supabase-проекте применяйте оригинальные миграции 001 и 002, затем 003. На текущем проекте четыре миграции установлены через Supabase connector.

Проект ранее прошёл 18 локальных тестов, но на работающей БД ещё не проверен пользовательский CRUD. Источник Белтуризм проверялся лишь на воспроизведённом HTML-фрагменте. Полноценную синхронизацию до реального теста адаптера включать нельзя.

1. Загрузите содержимое каталога `tourdesk` в GitHub репозиторий, не загружая `.env`.
2. В Render создайте **Web Service** из репозитория. Регион Frankfurt, Node, старт `npm start`, директория проекта `tourdesk` (если репозиторий содержит вложенную папку); проверка здоровья `/api/health`.
3. В **Environment** добавьте `SUPABASE_URL` = `https://guxkarncctfeiswevini.supabase.co`; `SUPABASE_ANON_KEY` = публичный anon/publishable ключ проекта из Supabase (не секрет); `APP_ORIGIN` = **точный HTTPS-адрес** созданного сервиса, например `https://tourdesk-XXXX.onrender.com`.
4. `SUPABASE_SERVICE_ROLE_KEY` — секретная серверная переменная, её нельзя публиковать в GitHub или отправлять в чат. Подключайте только после проверки безопасности. Без неё ручной CRUD и разбор текста могут работать, а синхронизация не будет активна.
5. Для периодических проверок на Render нужен отдельный worker/cron. Код есть (`npm run worker` или `POST /api/cron`), но не подключайте его, пока прямой тест HTML-ответа туроператора не пройден.
6. Проверьте регистрацию, подтверждение почты, вход и выход, создание и редактирование тура, несколько дат, избранное, историю цен, страницу обновлений, выход и повторный вход. Затем проведите тест синхронизации на отдельном тестовом туре.

**Стоимость:** настройка Render может зависеть от доступности бесплатного тарифа. Если предлагается платная конфигурация, подтвердите её перед созданием.

## Известные ограничения

- В `save_tour` дата выезда является уникальной внутри тура: несколько тарифов на одну дату пока не поддерживаются.
- Прямой живой парсинг Белтуризма не подтверждён.
- Сервис не защищён от DDoS/массовой регистрации дополнительными лимитами.
- Для профессионального запуска нужен сквозной тест безопасности и восстановления резервной копии.
