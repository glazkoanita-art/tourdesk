# Результаты проверки — TourDesk 0.2

Дата: 4 ноября 2026 г.

## Выполнено локально

- `npm test` — **18 из 18 тестов прошли**.
- HTTP-сервер `server/index.mjs` успешно стартует с Node.js 22.
- `GET /api/health` возвращает HTTP 200 и корректный признак отсутствующей конфигурации Supabase.
- HTML и CSS отдаются сервером с HTTP 200.
- Параметры дат, цен, валют, сохранения разных выездов, клиентских текстов и предохранители синхронизации проверены на уровне JavaScript-модулей.
- Разбор JSON-LD и текстового примера проверен на фикстурах.
- Частичный и пустой результат извлечения **не** считается достаточным для удаления даты.
- Домен для запрещённых внутренних адресов блокируется до HTTPS-запроса.
- Синтаксис JavaScript проверен `node --check`.

## Не проверено — нельзя считать завершённым

- SQL-миграция на реальной Supabase Postgres и права RLS.
- Повторный вход и сохранение туров между устройствами с подключённой облачной БД.
- Сквозное редактирование с одновременной записью в `price_history` и `departure_events`.
- Реальный сайт Global Travel: URL не удалось получить для достоверной проверки; адаптер не получает статус verified.
- Изменение цены / появление / исчезновение даты на реальном подключённом источнике.
- Отработка cron в постоянно включённой облачной инфраструктуре.
- Работа графического интерфейса в Chrome и мобильных браузерах: запуск Playwright был заблокирован средой (`ERR_BLOCKED_BY_ADMINISTRATOR` для localhost и file://).
- Динамические сайты с JavaScript-рендерингом, API/JSON/XML отдельных туроператоров, ИИ-разбор и полноценное командное администрирование.

**Итог:** тесты основы пройдены; проект не объявляется завершённой продуктивной системой до подключения Supabase и реального источника. Следующий этап — staging Supabase и сквозные тесты, затем пилот одного туроператора.


## Дополнительные проверки Белтуризм (04.11.2026)

В версии 0.2 добавлены 7 отдельных модульных тестов специализированного адаптера:

- Регистрация домена `belturizm.by` в реестре источников.
- Разбор 10 отдельных пар дат и соответствующих цен по наблюдаемому **текстовому** фрагменту сайта (тестовый HTML составлен из видимых элементов страницы, не является оригинальным HTML сервера).
- Наличие мест / отсутствие мест на двух отправлениях; продолжительность, включённые услуги и расходы.
- Запрет считать скрытые или не выведенные даты удалёнными.
- Отказ в автоматическом применении, если одна строка не имеет цены/часть календаря разобрана некорректно.
- Обработка `Br 1 540` как BYN и выявление смены EUR → BYN как возможной перемены валюты интерфейса.
- Отказ от `verified` при недоступном календаре.

**Фактически:** `npm test` — **18/18**, `node --check` для изменённых JavaScript-файлов — без ошибок.

**Ограничения:** реальный HTML не удалось скачать из среды сборки по причине недоступности DNS. Веб-страница была изучена отдельно через поисковое чтение, однако **сквозной GET HTML → адаптер → Supabase RPC не выполнялся**. PostgreSQL в этой среде недоступен; миграция `002_belturizm_availability.sql` не исполнялась. Экран телефона на реальном устройстве не проверен.

До включения рабочего планировщика нужны эти проверки. Механизм сохранения при сбое проверен тестами логики, но не интеграционно на базе данных.
